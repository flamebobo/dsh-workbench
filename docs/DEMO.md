# 研发工作台 · 演示手册（10/24）

演示的是 DSH 桌面版（0.2.1-rc.2）里的「工作台」插件：待办 → 开工 → 真实 DSH 会话 → 卡片自动流转。

## 1. 安装

先**完全退出** DSH 桌面端，再执行（只改 `desktop` profile）：

```bash
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add /Users/laihuibo/Documents/dsh-plugin/dsh-plugin
```

重新打开 DSH，左侧栏出现「工作台」。安装是 `link:`（指向仓库里的 `dsh-plugin/` 目录）：

- 改页面（`ui/`）：`npm run build`，刷新页面即可。
- 改 Host / core（`host/`、`core/`）：`npm run build` 后重启 DSH 桌面端。
- 仓库里已提交构建产物 `dsh-plugin/index.js`、`dsh-plugin/client.js`，同事机器不需要构建。
- 卸载：退出 DSH 后 `dsh plugin --profile desktop remove @local/workbench`。

## 2. 配置真实数据源（可选；不配就是演示数据）

在工作台的「设置」页填写（左侧选系统、右侧填内容，截图 `docs/demo/15-settings.jpg`）：

- **禅道**：地址、账号、密码；「执行 / 迭代 ID」可选。
- **GitLab**：地址、Access Token（需要 `read_api`）。
- **Jenkins**：地址、用户名、API Token（要能触发构建，才能用「构建验证」）。

每个系统有「保存」「保存并测试连接」「清除」。保存后立即生效，「我的待办」**自动拉取并每分钟刷新一次**（待办页右上角显示更新时间）；没配的系统继续显示演示数据，顶部「演示数据」标签点一下就跳到设置页。

- 凭据保存在 DSH 自己的凭据库（`~/.dsh/.credentials.yaml`，权限 600），页面只知道「是否已设置」，密码和 Token 不会回显到页面、也不进提示词和日志；Token / 密码栏留空表示不修改。
- 仍然兼容手写 `~/.dsh/.env` 的 `WORKBENCH_*` 变量（设置页保存的值优先）。
- 禅道 Bug / 任务：优先用「项目」页填的禅道产品 ID 和设置页的执行 ID；**都没填时自动发现**账号能看到的产品和进行中的执行（各最多 20 个），拉取指派给你的、未关闭的条目。
- 某系统接口失败（例如禅道 v1 REST 不可用）会降级为演示数据，待办页顶部出现红色提示并写明原因。

## 3. 重置演示数据

数据都在 `~/.workbench/workbench.json`，演示用的工作目录在 `~/.workbench/demo-repos/`。要回到干净状态：退出 DSH → 删除这两处 → 重新打开（首次启动会重新种入 7 个演示项目、5 个智能体）。

```bash
rm -rf ~/.workbench/workbench.json ~/.workbench/demo-repos
```

## 4. 五分钟演示脚本

> 提前量：BUG-4821 的会话大约 1 分钟结束，所以第 2 步尽早点「开工」，边讲边等。

1. **（0:00）待办页**。点侧栏「工作台」。说明：禅道 Bug/任务、GitLab 待我评审的 MR、Jenkins 失败构建合成一张表，按优先级排序；顶部「演示数据」标签表示当前没配凭据（配了就是「实时」）。点第一行 BUG-4821：右侧是背景、验收标准、关联信息（分支、构建、MR），底部是「开工」。
2. **（1:00）开工**。保持选中 BUG-4821 + 「全栈工程师」，点「开工（创建会话）」。页面自动切到**看板**：卡片 `WB-1` 出现在「进行中」，带转圈。看侧栏：`payment-core` 工作区下出现会话「WB-1 支付回调幂等修复」，点开：首条消息里是待办标题、背景、验收标准、关联信息，智能体正在读 `src/pay-callback.js`、跑测试。
3. **（2:30）自动流转**。会话结束后看板卡片**自动进入「待审核」**（不用刷新）。点卡片：详情里有指派智能体、状态、执行记录（最终回复）、「打开关联会话 ↗」。把卡片**拖到「已完成」**——强调「已完成」只能人来设置，智能体只能把它送到待审核。回「我的待办」，BUG-4821 标着 `WB-1`、状态已完成，详情底部不再有「开工」按钮（同一个来源编号只能开一张卡）。
4. **（3:30）智能体**。「智能体」页有 5 个预置角色，改一下全栈工程师的系统指令点「保存」→ 提示「已注册为 DSH 智能体预设」。点侧栏「新会话」→ 模式下拉里出现「工作台 · 全栈工程师」等 5 项：同一份配置，工作台和 DSH 原生会话共用。
5. **（4:15）手工任务（可选）**。看板任意列点 `+`，填标题、描述、验收标准（每行一条）、优先级、项目、智能体后「创建」：卡片进看板，同时出现在「我的待办」里（来源「手工」，有「手工」筛选）。选了项目的任务可直接「创建并开工」，或之后在待办页 / 卡片里点开工；已阻塞的卡片可重新开工。「任务描述」框和 DSH 输入框一样用：输入 `/` 弹出指令菜单（`/plan` 先出方案、`/goal` 设为长任务目标，选中后文字以 `/plan ` 开头）；输入 `@` 在**所选项目的工作目录**里模糊搜索文件（如 `@pcb` 找到 `pay-callback.js`），上下键 + 回车插入；`＋` 按钮、拖入弹窗、或直接粘贴截图，可以加图片和文档；链接直接写在文字里。开工时 `@` 引用的文件列进首条消息（相对工作目录），图片/文档作为真正的 DSH 附件随消息（或随指令）发出；选了 `/plan` 的任务，会话进入计划模式，智能体提交方案后卡片自动转到「待审核」，在会话里点「同意执行」即可继续。
6. **（4:30）项目**。「项目」页是项目卡片（名称、工作目录、各状态任务数、关联的 GitLab / 禅道 / Jenkins / Sparkin，有阻塞或待审核时亮「需处理 / 需关注」）。点卡片进入**项目概览**：项目事实、当前状态（进行中 / 待审核 / 阻塞）、近期构建、当前工作、等你处理（待复核、阻塞、待填工时），点任务直达看板卡片；「编辑」改映射和工作目录，开工时用工作目录当会话 cwd。可选演示出错路径：把「前端 / teleone-web」的工作目录改成一个不存在的路径，对 `teleone-web #887` 点开工 → 卡片直接进入「已阻塞」，卡片上写明原因（演示后改回去）。
7. **（4:45）构建验证**。看板右上角「构建验证」：勾选这批待审核/已完成的卡片，选（或输入）对应环境的 Jenkins Job，如 `order-service-test`，可填 `ENV=test` 这样的参数，「触发构建」。弹窗下方「最近构建」实时显示 排队中 → 构建中 → 成功/失败（带 Jenkins 构建号和链接），卡片上也会挂上构建状态。没配 Jenkins 时是模拟构建（标「演示」，约 15 秒后成功），流程一样可演示。
8. **（5:00）排序与自动运行**。每一列的卡片都能**拖动调整顺序**（拖到另一张卡片的上半部分 = 插到它前面，蓝线提示落点）。看板顶部显示「N 个智能体工作中」，旁边是「手动运行 / 自动运行」开关：手动 = 点「开工」才运行；自动 = 按「待办」列**从上到下依次开工，一次一个**，一个结束（进入待审核 / 已阻塞）再启动下一个，待办卡片上显示执行顺序 `#1 #2…`，运行中还能继续拖动调整后面的顺序、往待办里拖入或新建任务。没选项目的卡片会被跳过并提示；启动失败的卡片进「已阻塞」，队列继续。「待规划」「已归档」的卡片不会自动运行。
9. **（5:30）任务链、整理与工时**。打开一张卡片，「任务链」里选「下一个任务」或「＋新建后续任务」（继承项目和智能体）：后续任务开工时，首条消息会带上前置任务的结论；你把前置卡片拖到「已完成」时会问「接着开工下一个吗」。看板和「我的待办」顶部都有**搜索**（编号 / 标题 / 描述 / 智能体 / 项目）；卡片和待办都能**归档**（默认隐藏，勾「显示已归档」找回）或**删除**（不可恢复），「归档已完成」一键收起整批。卡片完成后点「填报 Sparkin 工时」：按所属项目对应到 Sparkin 的项目任务，填工时和日期，提交后卡片显示「已填报工时」。
10. **（6:00）待办排序与修改**。「我的待办」表头每一列都能点：点一次升序、再点降序（▲/▼ 标记；优先级按 P0→P3，截止按日期且无截止的始终在最后，文字按中文拼音）。选中一条点「编辑」就是看板同一张卡片表单（标题、描述含 `/` `@` 附件、验收标准、项目、优先级、智能体、状态）：手工任务直接改；禅道 / GitLab / Jenkins 条目会先在本地建一张「待规划」卡片（编号 `WB-n`）再编辑，改动在待办里覆盖原条目显示，**不会写回原系统**，之后仍可在待办里「开工」。截图 `26-todo-sort-edit.jpg`。
11. **（6:30）自动流转、Sparkin 待办、回写禅道**。状态按会话自动走：开工 →「进行中」→ 会话结束「待审核」→ 项目配了测试命令时自动跑测试，**通过后自动进入「已完成」**（设置 → 插件设置可关；没有测试命令、测试失败时仍由你验收）。在 DSH 会话里接着对话、或批准计划后智能体继续工作，卡片会自动回到「进行中」，结束后再回「待审核」。「我的待办」多了 **Sparkin** 来源（紫色，演示数据，预估工时和任务类型写在关联信息里）：开工后做完填报工时时，会直接选中这条 Sparkin 任务。禅道 **Bug** 卡片完成后出现「回写禅道」：弹出评论草稿（修复说明、测试结果、分支、MR，可修改），点「评论并改为已解决」才发送；设置里可改成完成即自动回写。没配禅道账号时是演示，只在卡片上记录。截图 `27-sparkin-todos.jpg`、`28-zentao-writeback.jpg`。
12. **（7:00）等你处理与周报**。「看板」标签上的红色数字是「待审核 + 已阻塞」的张数，提醒你有卡片在等；待审核的卡片上有「验收通过」（一键进已完成），已阻塞的有「重试」（同一智能体、沿用原分支重新开工）。看板顶部「生成周报」：把本周完成的卡片（含已归档）、待审核 / 进行中 / 已阻塞的事项和已填报工时汇总成一个交给「周报助手」的任务，放在「待规划」（自动运行不会自己开工），确认后点开工；同一周只生成一次。截图 `29-weekly-report.jpg`。
13. **（7:30）上线准备：引导、统计、通知、日报、技能包、安装更新**。
    - **首次使用引导**：第一次打开弹出两步引导——看各系统是否已连接；扫描本机目录里的 git 仓库，按 `git remote` 自动匹配 GitLab 项目 ID（需先配置 GitLab），测试命令按 package.json / go.mod / Cargo.toml 猜，勾选后一键建项目。「设置 → 插件设置 → 重新运行引导」可再打开。截图 `30-onboarding.jpg`。
    - **统计**页：开工数、完成数与完成率、审核通过率、合并请求、测试通过、已填报工时、智能体累计运行、近 8 周趋势、按智能体 / 来源，可导出 CSV / JSON。数据全部来自本机，不做估算。**匿名上报默认关闭**：在插件设置里填上报地址并开启，每天最多一次，只含汇总数字，发送前可在统计页看全文；也可点「立即上报」。截图 `31-stats.jpg`。
    - **桌面通知**：卡片进入「待审核 / 已阻塞」或禅道回写完成时弹系统通知（页面没打开也会弹，正在看工作台时不弹），点击打开对应卡片。设置里可开关，并有「授权并发送测试通知」。
    - **日报 / 周报**：看板顶部「日报 / 周报」按卡片、任务分支提交、已填报工时生成草稿，可编辑、复制，也可「交给周报助手润色」（生成待规划任务，自动运行不会开工）。不会自动发送到任何地方。截图 `32-report-draft.jpg`。
    - **技能包**：插件设置里填技能包目录（目录下每个技能是 `名称/SKILL.md`），保存后这些技能出现在 DSH 的技能列表里；「项目 → 编辑 → 项目规范技能」勾选后，这个项目的任务开工时自动加载。随包带了示例（`company-code-style`、`company-git-flow`），设置里点「添加示例技能包」即可演示。截图 `33-skill-packs.jpg`。
    - **安装与更新**：`npm run pack` 生成 `dist/workbench-plugin-<版本>.zip`（插件 + `install.sh` / `install.ps1` + 安装说明）和 `latest.json` 模板。同事解压后运行 `./install.sh`，DSH 在运行时会先询问是否退出，装完自动重开；更新 = 运行新版本包里的同一个脚本，数据保留。插件设置里填「更新地址」后，每天检查一次，有新版本时工作台顶部提示。数据文件带版本号，升级时先备份为 `workbench.json.v<旧版本>.bak`，来自更新版本的数据文件会被拒绝而不是被改写。截图 `34-update-banner.jpg`。
10. **（6:00）实战三件套：分支隔离 → 审查改动 → 提交 MR**。开工时（项目是 git 仓库）每个任务自动获得独立分支和工作树（`wb/wb-1-…`，在工作台数据目录的 `worktrees/` 下），智能体只在里面改，自动运行时多个任务互不干扰；会话结束后会自动运行项目配置的测试命令（演示的 payment-core 是 `node --test`）。打开卡片的「代码与验证」：看分支与基线、测试通过/失败（可看输出、可重跑）、「查看改动」逐文件看 diff（红绿着色，+/- 行数）。确认没问题后点「提交 MR」：提交改动、把分支推到 origin、在 GitLab 创建合并请求（描述里带背景、验收标准、测试结果和智能体总结），卡片和看板上显示 `MR !42 ↗`。这一步会对外推送，所以有确认弹窗，且只有点击才会执行。
11. **（7:00）智能体与插件设置**。「智能体」页除了名称、描述、系统指令，还能选**模型**、**模型强度**（从 DSH 实时读取，如 Off / Low / High / Max）和**关联技能**（多选，开工时在首条消息里用 `/技能名` 显式加载）。「设置 → 插件设置」集中管理原先写在代码里的值：自动运行同时跑几个、队列检查间隔、待办拉取间隔、各来源默认智能体、权限预设、分支隔离与前缀、自动测试与超时、附件上限、`@` 搜索条数、默认工时。
12. **（7:30）收尾**：配置 `~/.dsh/.env` 就能换成真实数据；下一步是回写禅道/GitLab、触发 Jenkins、接 Sparkin 工时，以及同一个 core 装进 Codex。

14. **待办与看板同步**。每条待办（禅道 / GitLab / Jenkins / Sparkin）会在看板「待规划」列自动有一张卡片，看板显示截止日期（过期标红）；「我的待办」里的「编辑」就是编辑这张卡片：标题、描述、验收标准、**截止日期、关联信息**、项目、优先级、智能体、状态都可以改，改动覆盖来源系统的显示、不写回原系统。你删除的卡片不会被下次拉取带回来（再点「编辑」或「开工」会重新建）；来源里已经没有的待办，它的待规划卡片会标注「来源系统里已不在你的待办中」而不是被删掉。自动运行只处理「待办」列，不会碰这些待规划卡片。可在「插件设置 → 待办同步到看板」关闭。截图 `35-edit-due-related.jpg`。

## 6. 已知限制
- **安装脚本**：`install.sh` 在 macOS 上用一个临时 profile 实测过安装、更新、拒绝误删目录、找不到 dsh 四种情况；**「DSH 正在运行时先询问并退出」这一段没有实测**（会退出正在使用的桌面端）；`install.ps1` 没有在 Windows 上运行过，DSH 在 Windows 上的安装路径是按常见位置猜的，找不到时用 `-DshPath` 指定。
- **桌面通知**：用的是浏览器的 Notification。macOS / Windows 需要在系统设置里允许 DeepSeek Harness 的通知；我在浏览器里验证了「入口轮询 → 触发通知 → 点击打开卡片」，没有在打包后的桌面端里看到真实的系统弹窗。
- **匿名上报 / 更新检查**：地址默认都是空的，不填就不会联网；我用本机的小服务验证过上报内容和检查更新，没有对接真实的内网地址。
- **技能包**：通过 DSH 的技能注册表提供（`ctx.skills.registerProvider`），目录里新增 / 修改技能在保存设置或打开技能选择器时才会被重新读取，不监视文件变化。
- **首次引导的 GitLab 匹配**：只在仓库的 remote 主机与已配置的 GitLab 一致时才查询；没配置 GitLab 或查不到时只建项目、不带项目 ID。
- **回写禅道**：调用 `POST /api.php/v1/bugs/{id}/resolve`（resolution=fixed，resolvedBuild=trunk，评论放在 comment 里，一次完成评论和改状态）。这个接口和字段来自第三方客户端的写法，**没有在真实禅道上验证过**，不同版本可能不同；单测只验证了请求形状。上线前请先用一个测试 Bug 试一次。只支持 Bug，不回写禅道任务和需求；一个 Bug 只回写一次。
- **自动完成**：只由「测试通过」触发（系统不会因为智能体说“做完了”就完成）。需要在设置里关掉时，「已完成」恢复为只能由你设置。
- **Sparkin 待办**：目前是演示数据（`DemoSparkin.assigned()`），真实接口接入时实现 `SparkinClient.assigned()`，其余流程不变。

- 真实的禅道/GitLab/Jenkins 连接器只对照接口文档与样例 JSON 做了单测，并用本地 mock 验证过「凭据 → 实时」这条路径；**没有对着公司真实实例跑过**，禅道开源版 v1 REST 的字段在不同版本可能有出入（失败会降级为演示数据并提示）。
- 附件单个上限 25 MB；`@` 搜索只扫工作目录（跳过隐藏目录、node_modules、dist 等，最多 2 万个文件）；指令只提供 `/plan` 和 `/goal`（需要自由文本输入且能起一轮对话的指令），不是 DSH 全部命令；附件在卡片创建时就存到 `~/.workbench/uploads/`，删除卡片时一并删除。
- `/plan` 任务在智能体提交方案时就转到「待审核」（这一轮要等你批准才结束）；你批准后智能体继续执行，卡片不会自动回到「进行中」。
- 自动运行同时跑几个由「设置 → 插件设置」的「同时运行的智能体数」决定（默认 1）；开关状态会保存，DSH 重启后若还是「自动运行」会继续按队列开工。自动运行跳过没选项目的卡片；`/plan` 等提交方案后等你批准的任务不占用名额。
- **分支隔离**：只对 git 仓库生效；工作树放在工作台数据目录的 `worktrees/<项目>/<编号>`，DSH 侧栏里每个任务会多出一个以编号命名的工作区；删除或归档任务时，只有工作树干净才会移除（有未提交内容会保留），分支一直保留。创建分支失败会让卡片「已阻塞」并写明原因，不会悄悄改到主目录。
- **提交 MR** 依赖：项目的 GitLab 项目 ID、仓库有 origin 远程、设置里配好 GitLab Token、本机 git 已能免密推送（用的是你机器上已有的 git 凭据，GitLab Token 只用于调用 API）。只创建 MR，不合并；同一分支已有打开的 MR 时会直接关联它。
- 测试命令按项目配置，在任务工作树里用 shell 执行（macOS/Linux 是 sh，Windows 是 cmd），请只填你信任的命令。
- 只跟踪会话的**第一轮** `turn/end`：卡片进入待审核/已阻塞后，你在会话里继续追问不会把卡片拉回「进行中」。
- DSH 重启时仍在运行的 run 会被对账为「已阻塞（宿主重启）」。
- **Sparkin 目前是演示后端**：项目、任务是内置的示例，「填报 Sparkin 工时」只把工时记在工作台里（卡片上标「演示」），不会写进真实的 Sparkin——需要 Sparkin 的 API 文档才能接入（接口层是 `core/src/sparkin.ts` 的 `SparkinClient`，实现 `projects / tasks / submit` 三个方法即可，页面和流程不用改）。
- 工时只能对「已完成」（由你设置）且未填报过的卡片填报，每张卡片只填一次；工时默认 1 小时，需要你按实际修改。
- 归档的「禅道 / GitLab / Jenkins」待办只是在工作台本地隐藏，不会影响原系统；删除卡片后，该条目只要在原系统里还存在，就会重新出现在待办里（编辑过的内容随卡片一起丢失，恢复为原系统的样子）。
- 工作台只读取禅道 / GitLab，不回写禅道、不提交 MR；Jenkins 只会触发你选的 Job 构建一次（`POST /job/<名>/build` 或 `buildWithParameters`，自动带 CSRF crumb），不会改 Job 配置。构建状态靠轮询 Jenkins 的队列项和构建接口，Job 需要参数而你没填会提示失败。
- Jenkins 触发、禅道自动发现同样只对照接口文档和 mock 验证过，没有对着公司真实实例跑过；Job 在文件夹里时用 `文件夹/Job名` 填写。
- 看板没有「归档」列；只用主题变量上色，暗色主题未逐页核对。
- 提供的智能体模型下拉只有 `deepseek-flash` / `deepseek-pro`，留空跟随 DSH 默认模型。
- 工作区下拉里会多出 `payment-core`、`teleone-order` 等演示工作区（DSH 在开工时登记的），可在 DSH 里自行移除。
