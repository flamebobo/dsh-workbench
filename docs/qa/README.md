## 待决定（需要产品判断，没有动）

1. **P1 · 实时来源失败时用演示数据顶替真实列表**：已配置凭据的系统出错时，待办里会混进假条目（BUG-4821 之类），点开工会对假条目起真实会话。现在是 DEMO 里写明的设计。建议：配置过凭据的来源失败时显示空列表加红色提示，只有没配凭据才用演示数据。
2. **P1 · 演示卡片在接入真实系统后不会清理**：留在「待规划」，标注「来源里已不在」。建议：设置页加「清理演示卡片」，或探测到某来源转为实时时自动清理没开过工、没编辑过的演示卡片。（回写真实禅道已由 Q15 拦住。）
3. **P2 · 「测试通过后自动完成」默认开启**本身是产品决策。已加「必须有改动」护栏（Q11）；想更保守可以默认关闭。
4. **P2 · 没有独立的完成时间**：统计周趋势、日报周报按最后更新时间算，已完成的卡片之后被编辑或提 MR 会换到更晚的一周。要加 `doneAt` 字段和一次数据版本迁移。
5. **P2 · 工作台没有「停止智能体」按钮**，只能去 DSH 会话里中断。
6. **P2 · 数据文件损坏（不是合法 JSON）时 Host 启动失败，没有任何界面提示**；是否自动改名备份并从空数据开始需要你定。

## 已发现、未修复的小问题（P2）

- 窄窗口（< 900px）下详情面板占一半宽度，待办表要横向滚动（`06`）。
- 自动运行队列的 `#1` 序号包含会被跳过的（没选项目的）卡片。
- 改了插件 / 点击卡片后，浏览器原生 `confirm()` 对话框在自动化里不可见（真实桌面端里正常弹出），所以「提交 MR」的确认是用脚本放行后测的。

## 靠 mock / 脚本验证的部分

没有对着任何真实系统运行。禅道（含回写）、GitLab（含创建 MR）、Jenkins（含触发与轮询）、更新检查、匿名上报都是 `scripts/qa/mock.mjs`，所有写请求记在 `http://127.0.0.1:4100/__log`（`evidence-double-click.txt` 是其中一份）；Sparkin 本来就是演示后端。MR 推送到的是本地裸仓库。智能体会话是真实的 DSH 会话（用 web profile 的账号模型，在 `~/.workbench-qa` 里的临时仓库上跑）。

没有验证：系统桌面通知的真实弹窗（只测了入口轮询逻辑）、`install.sh` / `install.ps1`、Windows、禅道回写和 `limit=200` 在真实禅道上的行为、DSH 桌面端本身（测试用的是 web profile）。
